1.4.5. Window & Scrolling¶

Description and Priority¶

Priority: Low

The window defines the total visible height, limiting the maximum number of visual lines that can be “displayed” at once. A window_height = 10 means that no more than 10 visual lines/ display lines are returned.

The viewport acts as a virtual boundary within the window. It constraints where the cursor can move before triggering a scroll. A viewport_height = window_height means there are no restrictions on where the cursor is displayed (window coordinate) withing the window.

ScrollOff defines the margin: the number of visual lines that must remain visible above and below the cursor. The cursor is only allowed to enter the scrollOff margins if it is near the absolute start or end of the text buffer where scrolling further is impossible.

The visible window range/ the window start is automatically updated in response to cursor movement and text manipulation.

State Invariants¶

Invariant: Display Dimensions INV-VIEW-001
tags: viewport, state
links outgoing: FR-INIT-004
links incoming: INV-CURSOR-001, INV-INIT-001, FR-INIT-004, FR-MODE-031

A positive integer display height must be defined at system initialization. It dictates the maximum number of visual lines the system can return as display lines.

Note: If dynamic resizing is needed by a user, the system must be re-initialized with a new display height.
Invariant: ScrollOff Constraint INV-VIEW-002
tags: viewport, scrolloff
links outgoing: FR-INIT-005
links incoming: INV-INIT-002, FR-INIT-005, FR-INIT-011

A non-negative integer scrollOff must be defined. To ensure a valid viewport height exists, the condition 2 * scrolloff < display_height must strictly hold true.
Invariant: Window Bounds INV-VIEW-003
tags: viewport, boundaries
links incoming: INV-INIT-002, FR-INIT-007, FR-MODE-031

The visible window is defined by a window start index (representing the first visible visual line index).

The window must always be contained within the available visual lines. The valid range is:

0 <= window_start <= max(0, num_visual_lines - display_height).
Invariant: Viewport Subset INV-VIEW-004
tags: viewport, boundaries
links incoming: INV-INIT-002

The viewport is the subset of the display lines excluding the top and bottom scrollOff lines: [scrolloff, viewport_height + scrolloff].

The viewport height is strictly display_height - (2 * scrolloff) and positive.

Preconditions¶

The system requires an initialized text buffer that has been successfully mapped into visual lines according to the Wrapping Specification.

Stimulus/Response Sequences¶

  • Stimulus: The cursor is moved to a new position within the bounds of the current viewport.

    Response: The system requires no scrolling action; the window remains unchanged.

  • Stimulus: The cursor is moved to a position outside the current viewport (into the scrollOff region or beyond).

    Response: The system adjusts the window start by the minimal amount required to include the new cursor position within the viewport.

  • Stimulus: Text is deleted, reducing the total number of visual lines such that the current window start violates Window Bounds (INV-VIEW-003).

    Response: The system automatically shifts the window start upwards (decreasing the value) until the window bounds are valid again.

Functional Requirements¶

Requirement: Cursor Window Constraint FR-VIEW-001
status: Open
tags: viewport, scrolloff
links incoming: FR-INIT-007

The system must enforce that the cursor remains within the window/ display lines at all times.

In other words: the y value of the window coordinate must be within the range [0, num_display_lines-1]. (Together with Coordinate Synchronization (INV-CURSOR-003)) (Since there is always at least one logical line (Empty Buffer Definition (INV-TEXT-001)), num_display_lines will always be at least 1.)
Requirement: Cursor Constraint & Scrolloff FR-VIEW-002
status: Open
tags: viewport, scrolloff
links incoming: FR-VIEW-003

The system must enforce that the cursor remains within the viewport whenever mathematically possible.

This constraint must only be relaxed (allowing the cursor into the scrollOff region) when the window start has reached the absolute start or end of the text buffer and prevent the window from scrolling further (i.e., when window_start == 0 or window_start == max(0, len(visual_lines) - display_height)).
Requirement: Minimal Scroll Adjustment FR-VIEW-003
status: Open
tags: viewport, scrolling
links outgoing: FR-VIEW-002

When adjusting the window, the system must change the window start index by the absolute minimum amount required to satisfy Cursor Constraint & Scrolloff (FR-VIEW-002).
Requirement: Non-Destructive Scrolling FR-VIEW-004
status: Open
tags: viewport, scrolling
links outgoing: FR-CURSOR-005

Scrolling operations must adjust only the window start index, window coordinate and the display lines. They are a purely visual mechanism and must not change the Absolute Index, Logical, or Visual Coordinates of the cursor, nor modify the text buffer.

Scrolling operations may adjust the Window Coordinate [x, y] of the cursor only in some cases.
