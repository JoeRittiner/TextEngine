1.4.1. System Initialization¶

Description and Priority¶

Priority: High

Initialization is the process by which the TextEditor is created/ brought into a valid, operational state. During initialization, the host application supplies all parameters required to configure the system, and the TextEditor constructs a self-consistent internal state from them.

No text manipulation, cursor movement, or output operations can be performed until the system is successfully initialized. A failed initialization must not produce a TextEditor instance.

Initialization is a one-time operation per TextEditor instance. To change any configuration parameter (e.g., Display Width, Display Height, or ScrollOff), the host application must discard the current instance and initialize a new one.

State Invariants¶

Invariant: Immutable Configuration INV-INIT-001
tags: initialization, configuration
links outgoing: INV-WRAP-001, INV-WRAP-002, INV-VIEW-001
links incoming: FR-INIT-001

Once the TextEditor is successfully initialized, the values of Display Width, Display Height, and ScrollOff must remain constant for the lifetime of that instance. They may not be mutated by any operation after initialization.
Invariant: Post-Initialization Validity INV-INIT-002
tags: initialization, state
links outgoing: INV-CURSOR-001, INV-VIEW-002, INV-VIEW-003, INV-VIEW-004
links incoming: FR-INIT-001

Upon successful initialization, all system invariants must be satisfied simultaneously. The resulting state must be indistinguishable from a state reached by the normal operation of the system.

Specifically, the following must hold:

  • The Text Buffer contains the provided initial text (or is empty: Empty Buffer Definition (INV-TEXT-001)).

  • The Cursor Absolute Index is within [0, len(text_buffer)].

  • All coordinate representations of the Cursor are consistent with each other and with the Text Buffer contents (Coordinate Synchronization (INV-CURSOR-003)).

  • 0 <= window_start <= max(0, num_visual_lines - display_height) (Window Bounds (INV-VIEW-003)).

  • The Cursor is positioned within the Viewport or within a ScrollOff margin, as permitted by Cursor Window Constraint (FR-VIEW-001).

Preconditions¶

None. Initialization is the entry point of the system and has no preconditions beyond the parameters supplied by the host application.

Stimulus/Response Sequences¶

  • Stimulus: The host application requests initialization of a TextEditor with a valid set of parameters (display_width, display_height, scrolloff, and optionally text and cursor_index).

    Response: The system validates all parameters, constructs the internal Text Buffer, computes all visual lines, places the Cursor at the specified or default position, and sets the Window Start to the minimal value that satisfies Cursor Window Constraint (FR-VIEW-001). The TextEditor enters an operational state and is ready to accept further commands.

  • Stimulus: The host application requests initialization with one or more invalid parameters (e.g., display_width = 0, scrolloff violating ScrollOff Constraint (INV-VIEW-002), a cursor_index out of range, or a type mismatch).

    Response: The system raises an exception describing the violated constraint. No internal state is constructed or mutated. The TextEditor remains inert.

Functional Requirements¶

Happy Path¶

Requirement: System Initialization FR-INIT-001
status: Open
tags: initialization
links outgoing: INV-INIT-001, INV-INIT-002

The TextEditor must be initialized by the host application by supplying the following parameters:

  • Initial text - optional; defaults to an empty string (see Text Initialization (FR-INIT-002)).

  • Display Width (display_width) - required (see Display Width Initialization (FR-INIT-003)).

  • Display Height (display_height) - required (see Display Height Initialization (FR-INIT-004)).

  • ScrollOff (scrolloff) - required (see ScrollOff Initialization (FR-INIT-005)).

  • Initial cursor position - optional; defaults to the end of the Text Buffer (see Cursor Initialization (FR-INIT-006)).

Window Start is not a host-supplied parameter. It is computed by the system during initialization (see Post-Initialization Validity (INV-INIT-002), Window Start Initialization (FR-INIT-007)).

The system must not expose any observable state until initialization completes successfully.
Requirement: Text Initialization FR-INIT-002
status: Open
tags: initialization
links outgoing: FR-TEXT-017

The host application may supply an initial text string at initialization.

If initial text is provided, the resulting Text Buffer state must be identical to that produced by initializing the system with no text and then inserting the provided string in full, as per Insert Atomicity (FR-TEXT-017).

If no text is provided, the system must initialize the Text Buffer to an empty string, equivalent to a single empty logical line.
Requirement: Display Width Initialization FR-INIT-003
status: Open
tags: initialization
links outgoing: INV-WRAP-001, INV-WRAP-002
links incoming: INV-WRAP-001, INV-WRAP-002

The host application must supply a positive integer value for Display Width at initialization.

If the value is zero, negative, or not an integer, the system must raise an exception and halt initialization (see ScrollOff–Height Conflict (FR-INIT-011), Type Conflict (FR-INIT-013)).
Requirement: Display Height Initialization FR-INIT-004
status: Open
tags: initialization
links outgoing: INV-VIEW-001
links incoming: INV-VIEW-001

The host application must supply a positive integer value for Display Height at initialization.

If the value is zero, negative, or not an integer, the system must raise an exception and halt initialization (see ScrollOff–Height Conflict (FR-INIT-011), Type Conflict (FR-INIT-013)).
Requirement: ScrollOff Initialization FR-INIT-005
status: Open
tags: initialization
links outgoing: INV-VIEW-002
links incoming: INV-VIEW-002

The host application must supply a non-negative integer value for ScrollOff at initialization. A value of 0 is valid and disables the scroll margin entirely.

If the value is negative or not an integer, the system must raise an exception and halt initialization (see ScrollOff–Height Conflict (FR-INIT-011), Type Conflict (FR-INIT-013)).

Note

A scrolloff value that violates the cross-parameter constraint 2 * scrolloff < display_height is rejected by Null Parameter (FR-INIT-012), even if the individual value is otherwise a valid non-negative integer.
Requirement: Cursor Initialization FR-INIT-006
status: Open
tags: initialization
links outgoing: INV-CURSOR-001
links incoming: FR-INIT-007

The host application may supply an Absolute Index to set the initial Cursor position. The value must satisfy 0 <= cursor_index <= len(text_buffer) after the Text Buffer has been constructed per Text Initialization (FR-INIT-002).

If no cursor position is provided, the system must default to len(text_buffer), placing the Cursor immediately right of the last character in the Text Buffer.

If a value outside the valid range (negative, or greater than len(text_buffer)) or a non-integer is provided, the system must raise an exception and halt initialization (see ScrollOff–Height Conflict (FR-INIT-011)).

Note

Logical Coordinate, Visual Coordinate, and Window Coordinate are not host-supplied parameters. There is currently no support for setting this values by the host application, even after initialization. Changing the Cursor position must be done via movement commands.
Requirement: Window Start Initialization FR-INIT-007
status: Open
tags: initialization
links outgoing: FR-VIEW-001, FR-INIT-006, INV-VIEW-003

The Window Start is not supplied by the host application. The system must derive it automatically during initialization.

The system must set Window Start to the smallest non-negative integer value that satisfies both Window Bounds (INV-VIEW-003) and Cursor Window Constraint (FR-VIEW-001) given the initial Cursor position.

If the initial Cursor position falls within the Viewport at window_start = 0, the system must set window_start = 0.

Conflicts and Error Conditions¶

Requirement: ScrollOff–Height Conflict FR-INIT-011
status: Open
tags: initialization, conflict
links outgoing: INV-VIEW-002

If the condition 2 * scrolloff >= display_height holds after both ScrollOff and Display Height have been validated individually, the system must raise an exception and halt initialization. No partial state must be constructed.

This constraint is checked after Display Height Initialization (FR-INIT-004) and ScrollOff Initialization (FR-INIT-005) have each passed their individual validations, as it requires both values to be present.
Requirement: Null Parameter FR-INIT-012
status: Open
tags: initialization, conflict

If a null (or language-equivalent absent) value is passed to any required parameter (display_width, display_height, or scrolloff), the system must raise an exception and halt initialization.

Note

Optional parameters (text, cursor_index) have defined default behaviors when absent and must not raise an exception when omitted or null.
Requirement: Type Conflict FR-INIT-013
status: Open
tags: initialization, conflict

If a value of an incorrect type is passed to any parameter, the system must raise an exception and halt initialization.

Examples of invalid types:

  • A float (e.g., 1.5) in place of an integer for display_width, display_height, scrolloff, or cursor_index.

  • A non-string value in place of a string for the initial text.

  • Exception null (or language-equivalent absent) values for the optional parameters (text, cursor_index) are allowed.

Out of Scope¶

Non-Requirement: Re-Initialization NR-INIT-101
tags: out-of-scope, initialization

The system does not support in-place re-initialization or mutation of configuration parameters (display_width, display_height, scrolloff) after successful initialization. To change these values, the host application must instantiate a new TextEditor instance.
Non-Requirement: State Persistence NR-INIT-102
tags: out-of-scope, initialization

The system does not provide mechanisms for serializing or deserializing its internal state. Saving and restoring editor state (e.g., for crash recovery or session resumption) is the responsibility of the host application, which may serialize the Text Buffer contents and cursor position via the output interfaces and supply them as initialization parameters to a new instance.
