1.4.4. Text Wrapping¶

Description and Priority¶

Priority: Medium

Logical lines that exceed the display width are not truncated or hidden. Instead, they are segmented into multiple visual lines.

Wrapping is a purely visual transformation and does not modify the underlying text buffer. No “soft” or “hard” newline characters are inserted into the text buffer to facilitate wrapping. This mechanism determines the mapping between the Absolute Index and Visual Coordinates as described in the Cursor Specification.

Note

The current implementation uses “Character Wrapping” (breaking at the exact display width boundary). Future iterations may introduce “Word Wrapping” logic.

State Invariants¶

Invariant: Defined Display Width INV-WRAP-001
tags: wrap
links outgoing: FR-INIT-003
links incoming: INV-CURSOR-001, INV-INIT-001, FR-INIT-003

A positive integer display width (representing the maximum number of characters per visual line) must be defined at system initialization.
Invariant: Static Display Width INV-WRAP-002
tags: wrap
links outgoing: FR-INIT-003
links incoming: INV-INIT-001, FR-INIT-003

The display width must remain constant during the lifetime of the system instance.

Note

To simulate a responsive or dynamic width, the environment must re-initialize the system component with the updated width value.
Invariant: Visual Line Integrity INV-WRAP-003
tags: wrap

The sum of the lengths of all visual lines associated with a logical line must equal the length of that logical line.

Preconditions¶

All wrapping logic assumes a valid text buffer as defined in Text Buffer Specification. Wrapping is applied automatically whenever the text buffer state changes or the system is initialized.

Stimulus/Response Sequences¶

  • Stimulus: The text buffer is modified (insertion, deletion, or initialization).

    Response: The system recalculates the break points for all affected logical lines and updates the total visual line-count and cursor Visual Coordinates.

Functional Requirements¶

Requirement: Non-Destructive Wrapping FR-WRAP-001
status: Open
tags: wrap

Wrapping operations must not alter the contents of the text buffer.

Joining all visual lines (excluding the implicit visual break) must perfectly reconstruct the original logical line.
Requirement: Full Content Visibility FR-WRAP-002
status: Open
tags: wrap

The system must not truncate or omit characters from the visual lines. Every character in the text buffer must be assigned to exactly one visual line.
Requirement: Break Logic (Character-Based) FR-WRAP-003
status: Open
tags: wrap
links incoming: FR-CURSOR-010, FR-MODE-021

A logical line is split into visual lines of length display_width, except the last, whose length is logical_line_length % display_width (or display_width if zero).
Requirement: Line Isolation FR-WRAP-004
status: Open
tags: wrap

Wrapping must be performed on a per-line basis. The system must never combine characters from two different logical lines into a single visual line.
Requirement: Empty Line Handling FR-WRAP-005
status: Open
tags: wrap

A logical line with zero characters must result in exactly one visual line with a length of zero.

Out of Scope¶

Non-Requirement: Character Boundary Flexibility NR-WRAP-101
tags: wrap, out-of-scope

Wrapping may occur at any character boundary. Word boundaries do not need to be preserved.
