1.4.6. Output Modes¶

Description and Priority¶

Priority: High

The system must provide four distinct output modes to support different levels of abstraction for external interfaces: Display, Wrapped, Logical, and Raw. See Software Interfaces.

These modes allow consumers to view the text buffer as a raw string, a collection of logical lines, a fully wrapped text buffer (visual lines), or a windowed viewport (display lines).

State Invariants¶

Invariant: Read-Only Operations INV-MODE-001
tags: mode, state

Requesting output in any mode must be a non-destructive operation. It must not modify the text buffer, change the cursor position, or alter the viewport range.
Invariant: Buffer-Based Idempotency INV-MODE-002
tags: mode, state

For Raw, Logical, and Wrapped modes, the output must remain identical across multiple requests as long as the text buffer state remains unchanged.
Invariant: Viewport-Dependent Idempotency INV-MODE-003
tags: mode, state

For Display Mode, the output is a function of both the text buffer state and the current viewport range. The output only remains identical if both the buffer content and the window boundaries (window start) are unchanged.

Preconditions¶

All operations in this section assume a valid text buffer as per Text Buffer & Manipulation.

All operations in this section assume a valid display width as per Text Wrapping.

All operations in this section assume a valid display height and viewport as per Window & Scrolling.

Stimulus/Response Sequences¶

  • Stimulus: An external consumer requests the buffer content in a specific output mode.

    Response: The system evaluates the current state against the requested mode’s logic and returns the formatted data.

Functional Requirements¶

Raw Mode¶

Requirement: Raw Text Output FR-MODE-001
status: Open
tags: raw mode, mode

The system must provide an interface to return the entire content of the text buffer as a single, continuous string of characters.

This output must include all newline characters (\n) exactly as they exist in the buffer without modification.

Logical Mode¶

Requirement: Logical Line Output FR-MODE-011
status: Open
tags: logical mode, mode

The system must provide an interface to return the contents of the text buffer as a sequence of logical lines.

The sequence must be split at newline characters (\n), and the newline characters themselves must be excluded from the returned strings.

Wrapped Mode¶

Requirement: Wrapped Visual Output FR-MODE-021
status: Open
tags: wrapped mode, mode
links outgoing: FR-WRAP-003

The system must provide an interface to return the entire text buffer as a sequence of visual lines, calculated based on the current display_width.

The wrapping logic must strictly follow Break Logic (Character-Based) (FR-WRAP-003).
Requirement: Visual-to-Logical Mapping FR-MODE-022
status: Open
tags: wrapped mode, mode

The output for Wrapped Mode must include metadata or a structural representation indicating which visual lines belong to which logical line.

Display Mode¶

Requirement: Viewport-Truncated Output FR-MODE-031
status: Open
tags: display mode, mode
links outgoing: INV-VIEW-001, INV-VIEW-003

The system must provide an interface to return only the subset of visual lines currently visible within the window.

The number of lines returned must not exceed the display height, and the content must correspond to the range defined by window start.
Requirement: Display-to-Logical Mapping FR-MODE-032
status: Open
tags: display mode, mode

The output for Display Mode must include metadata indicating which display lines belong to which logical line.

Out of Scope¶

Non-Requirement: Rendering & I/O NR-MODE-101
tags: out-of-scope

The system does not handle any rendering or GUI operations.
