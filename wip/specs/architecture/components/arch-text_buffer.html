Text Buffer¶

Responsibility¶

The TextBuffer is the single authoritative store for the content of the document. It accepts mutation operations (insert, delete, backspace) at a given absolute index and exposes the resulting text as a raw string. It is the only component permitted to hold or modify the underlying text. (Text Buffer (FR-TEXT-001), Text Buffer Mutation (FR-TEXT-002))

TextBuffer receives operations with an explicit index from LogicalDomainService internally, while the service’s own public API is cursor-centric and takes no index.

Owned State¶

The TextBuffer owns one piece of state: the raw text string. This is the ground truth of the document. All other representations of the text (logical lines, wrapped visual lines, window-clipped output) are derived from this string by other components.

The TextBuffer does not own a cursor position.
The TextBuffer operates exclusively on absolute indices passed to it by its callers.

Behaviour¶

Insertion is always a pure splice: characters are inserted at the given absolute index without overwriting existing content. (No Overwrite (FR-TEXT-014)) Inserting an empty string is a no-op. (Inserting Nothing (FR-TEXT-013)) Inserting a multi-character string produces the same buffer state as inserting each character sequentially. (Insert Atomicity (FR-TEXT-017))

Delete targets the character immediately to the right of the given index. Deleting past the end of the buffer is a no-op. (Delete Operation Support (FR-TEXT-021), Single Character Deletion (FR-TEXT-022), Delete Boundary Behavior (FR-TEXT-024)) Note: Cursor Position on Delete (FR-TEXT-023) Relates to Cursor Position, which is not a concern of the TextBuffer.

Backspace targets the character immediately to the left of the given index. Backspacing past the start of the buffer is a no-op. (Backspace Operation Support (FR-TEXT-031), Single Character Deletion (FR-TEXT-032), Backspace Boundary Behavior (FR-TEXT-034)) Note: Cursor Position on Backspace (FR-TEXT-033) Relates to Cursor Position, which is not a concern of the TextBuffer. Note: The TextBuffer does not natively support a backspace operation, only delete. This is because backspace also requires a cursor position, which is not a concern of the TextBuffer. A backspace operation is orchestrated by the LogicalDomainService.

Dependencies¶

The TextBuffer depends on nothing. It has no imports from other engine components and uses only the Python standard library.

Key Invariants¶

  • Buffer always exists. The buffer always represents at least an empty buffer containing zero characters. (Empty Buffer Definition (INV-TEXT-001))

  • Left-to-right processing. Characters are indexed 0-based from left to right. Index 0 is the leftmost character in the buffer. (Left-to-right Script (INV-TEXT-002))

  • Post-initialisation validity. After initialisation, the buffer contains exactly the provided initial text (or is empty), and this state is indistinguishable from one reached through normal operation. (Post-Initialization Validity (INV-INIT-002))

  • Output stability. For any given buffer state, repeated queries for raw text return identical results. Output is a pure function of the buffer contents. (Buffer-Based Idempotency (INV-MODE-002))
